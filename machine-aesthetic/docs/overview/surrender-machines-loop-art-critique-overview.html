What this is

Surrender Machines is a generative art project built on a single thesis: one species, one seed, many bodies. A piece of code — driven by three human forces (anger, ego, attachment) — generates a mechanical system that builds itself up, breaks down, and accumulates damage over time. That same underlying organism, called Machine DNA, expresses itself across three physical scales: a browser-based digital work, a console-scale object, and a room-sized installation. All three share one genome, one set of scars, and one nervous system (OSC) — they are not three separate artworks, but three bodies of the same living system.

The public-facing language is deliberately human, not technical: surrender, lifespan, mechanical sigh, scars, kintsugi, zero state. The work is about what it means to build a machine that includes emotion — and that, ultimately, cannot resolve those emotions for you. The first sentence of any description of this project should be about that, not about Three.js or Raspberry Pi.

Project narrative

Why this exists, and what it means
Where it comes from

Mark Walhimer spent decades in museum planning — designing spaces where the visitor is positioned as an audience: in front of the work, moving around it, leaving changed. Surrender Machines began from the opposite impulse: building something that doesn't hold still while you look at it. Something that knows you're there and responds, not as a feature, but as a condition of its existence.

The core idea

Surrender Machines is a generative mechanical system driven by three sliders: Anger, Ego, and Attachment.

Anger → gears
At low values the gears turn steadily. As anger increases, they spin out, jitter, and begin destroying themselves.
Ego → structure
Builds the structure — more platforms, more columns, more ambition — and produces sharp interference static above roughly 65%.
Attachment → grain
Multiplies the pulleys and rods, the connective tissue that holds on, generating a slow drifting grain that accumulates and never clears.

"The machine cannot surrender for you. That is the point."

At peak complexity — around 65% on each axis — the machine is at its most ornate and chaotic. Past that point, it begins destroying itself in its own specific way. There is a button: Surrender. But the machine cannot press it.

The concept is not about defeat — it's about acceptance as an active, repeated choice. We all carry frustrations, irritations, attachments we can't resolve through force. The machine makes the structure of that problem visible — the sliders are literal — but it cannot make the choice itself. That gap, between a system that can model a human condition and a system that cannot resolve it, is the center of the work.

How it grew

Surrender Machines was the first work in a broader line of inquiry — what Walhimer calls Machine Aesthetics. The next work, Acceptance Feed, asked what happens when the human body enters the loop: a webcam-derived breath estimate becomes a depth map, rendering the viewer back to themselves as a breathing point cloud. The current evolution, Machine Aesthetic (developed for the Loop Art critique at ICA Miami, Cohort #21, 2026), scales these same ideas — and the same code — into a full room: four walls, a piano, a generative DNA lifecycle that blooms, holds, reverses, and releases.

Across all of this, one principle holds: the code is the origin and the authority. A screenshot is not the work. A video of the work is not the work. Any physical form — object or room — has to remain faithful to what the running code actually does.

Why three bodies, one organism

The project's distinguishing idea is that these aren't separate pieces re-skinned for different contexts — they are one organism with three bodies.

What connects them is Machine DNA — a generative genome (seed, generation, scars, vitality) and a shared real-time protocol (OSC) so that every body is an expression of the same underlying state, not a second creative brain. Damage, wear, and history accumulate as scars — a kintsugi-like model where breakage becomes part of the visible record of the piece, and that record can be carried and merged across venues.

Comparable context

There's no shortage of generative AV art, OSC-driven installations, or dynamic NFTs individually. What's less common is the combination — a single genome with cross-venue scars, an operator layer, a persistent data record, OSC-driven physical bodies, a daily publishing/minting practice, and three physical scales, all as one species. That combination is still largely open territory. Reference points like deafbeef (generative AV + crypto), Chris Burden's Metropolis II (kinetic systemic scale), and Zimoun's motor-driven sound installations (emergent individuality from identical components) are useful comparisons rather than direct precedents.

Technical description

Architecture · accomplished · in design · scope
System architecture

The system is organized in four layers. Critically, only one layer makes creative decisions — everything downstream simply expresses that decision.

OPERATOR LAYER Phone / touch / buttons / camera → sends control signals only INSTALL BRAIN (one per venue — "dna-bridge") · Runs the Machine DNA kernel: seed, generation, scars, vitality · Reads operator input · Optional camera/vision sidecar (motion, presence — signals only) · This is the single creative authority → Supabase — genome + scars, persistent record, cross-venue merge → Firebase — live genome state for display/HUD → OSC (:7400) — real-time bus to installation bodies (OF, Pi, Linux Pd) → Plain UDP (:7401) — development audio path (Mac Pd) BODIES (expression only — no independent decision-making) Browser · room (OpenFrameworks) · console LCD · audio (Pd/DSP) · LED hardware (Pi/Teensy) · projectors · kinetic elements · (future) drawing arm OPS LAYER (separate) Daily catalog / minting pipeline · Transient Labs · social publishing → On mint, creates a new genome record (planned)
Operating rules
Operator layerNever makes creative decisions — only sends inputs (camera/touch/phone, future vision data)
SupabasePermanent record of genome state + scars; cross-venue merge (~15 min sync window)
OSCReal-time path for local, time-sensitive signals — never video or audio streams directly
Mint platformsProvenance and sales only — do not drive or replace the DNA system

The object prototype — in design
1 · Enclosure & brain
A compact dedicated computer running the DNA bridge, OpenFrameworks, Pd, and (later) vision — housed in a ~24×24" plywood/acrylic enclosure with networking, an LCD status display ("ON / OSC Active"), a touch screen or physical buttons, an LED driver (Teensy-based), small projectors (deferred), speakers, motors, and cooling.
2 · Sound & concept
A hardware synthesizer/sequencer (Roland S-1) acting as a "performer" voiced through Pd (not a second creative brain), plus sample and tracker-style sources for generative audio layers.
3 · Camera + machine learning
One or more small cameras feed a vision sidecar running on the main computer. Raw video never leaves that computer — only derived signals (motion energy, presence, zone) are sent to the operator layer or over OSC. Phase 1: a single motion-energy value mapped to speed or a fan trigger. Phase 2: zone-based, canvas-aware feedback. Video never travels over the cloud operator channel; ML never runs on microcontroller-class hardware.
4 · Kinetic / atmospheric (deferred)
Fans, silk, and sensors as a "breathing" pneumatic layer; steam effects; a robotic drawing arm — all parked until the room-scale phase.
